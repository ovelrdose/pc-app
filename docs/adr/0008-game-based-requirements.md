# ADR 0008. Требования к железу по играм клиента, монитор одним вопросом

- Статус: принято
- Дата: 2026-10-30
- Затрагивает: `docs/architecture.md` §5.2, §6.5, §8; `knowledge/questionnaire.yaml`,
  `knowledge/tables/games.yaml`, правила PRF/REQ/GOL; код `backend/app/expert/{game_needs,
  questionnaire,tables,facts,vocabulary}.py`, `expert/explanation/infeasible.py`

## Контекст

Класс игровой нагрузки выводился из разрешения и частоты монитора (PRF-031…038). По классу
задавались требования к видеокарте (REQ-006…010) и процессору (REQ-016…018). По сути частота
монитора считалась целевым FPS для любой игры: «2K на 165 Гц» означало высокий класс, процессор от
95 и видеокарту от 135. Автор проекта оспорил это решение по двум причинам.

1. **Частота монитора не задаёт количество кадров.** Видеокарта рендерит столько, сколько может,
   монитор только обновляет экран. С VRR (FreeSync, G-Sync) 70–90 кадров на 144 Гц выглядят
   плавно. Нужная плавность зависит от игры: в CS2 высокий FPS — часть игры, в Cyberpunk
   хватает 60.
2. **Разрешение и частота спрашивались двумя независимыми вопросами.** Из-за этого можно было
   собрать нетипичную пару, например «2K на 60 Гц».

Эвристические пороги («1080p 120–165 Гц → индекс 95») не опирались на данные. При этом в
справочнике игр уже были средний FPS на эталонной видеокарте и потолок FPS на эталонном
процессоре.

## Решение

1. **Монитор — один вопрос** со списком реальных типов. Каждый вариант записывает два факта,
   `user.resolution` и `user.refresh_hz`:

   | Вариант | Частота, которая записывается |
   |---|---|
   | Full HD 60–75 Гц | 60 |
   | Full HD 144–165 Гц | 144 |
   | Full HD 240+ Гц | 240 |
   | 2K 144–180 Гц | 144 |
   | 2K 240+ Гц | 240 |
   | 4K 60 Гц | 60 |
   | 4K 120–165 Гц | 144 |
   | «не знаю» | факты не записываются |

   «2K 60 Гц» убран: это рабочие мониторы, для игровой анкеты нетипичные. Для этого у варианта
   выбора появилось поле `facts` — какие факты он записывает. Поле проверяется по словарю:
   факт должен быть входным, значение допустимым, тип совпадающим.
2. **Комфортный FPS у каждой игры** — поле `target_fps` в `games.yaml`, знание эксперта:

   | Игры | Комфортный FPS |
   |---|---|
   | Соревновательные шутеры | 240 |
   | Rocket League | 144 |
   | Онлайн-игры и MOBA | 100 |
   | Doom | 90 |
   | Одиночные | 60 |
   | Стратегии и симуляторы | 45 |

   Цель для игры — `min(target_fps, частота монитора)`: кадры сверх частоты монитор не покажет.
   В снимках БЗ без этого поля берутся значения по виду игры: киберспорт — 144, AAA — 60.
3. **Требование считается по играм клиента** обращением формулы прогноза FPS:
   ```
   индекс видеокарты = 100 × цель / base_fps[разрешение][настройки]
   индекс процессора = 100 × цель / cpu_fps_cap
   ```
   - Соревновательные игры считаются на средних настройках, остальные — на высоких.
   - Игры с обязательной трассировкой считаются по индексу трассировки с множителем 0.6.
   - Если клиент назвал игры, итог задаёт самая требовательная из них.
   - Если не назвал — эталон заявленного сценария: CS2 для киберспорта, Cyberpunk 2077 для
     современных игр. Самая тяжёлая игра типового набора (Alan Wake 2) завысила бы требование
     для клиента, который о ней не говорил.
   - Результат записывается **вычисляемыми фактами** `need.*` (новое пространство имён): индексы,
     название игры и её цель. Это делается при переводе ответов в факты, до вывода.
4. **Требование — вычисляемый факт, а не пачка правил «по игре».** Конфликт значений решается
   по уверенности, а не по максимуму (§3.3 вики), поэтому из правил «по игре» победило бы
   случайное, а не самое требовательное.

   Правила ссылаются на свойство `need.*`, а не перечисляют игры:
   - REQ-053 — видеокарта, если игры основная задача, CF 0.9;
   - REQ-054 — трассировка лучей;
   - REQ-055 — процессор, только если нужно больше базового «не ниже среднего» (REQ-018, 85);
   - REQ-056 — видеокарта желательна, если игры дополнительная задача, CF 0.4.
5. **Класс игровой нагрузки** выводится из `need.gpu_raster` (PRF-052…055): лёгкая < 75,
   средняя 75–120, высокая 120–185, экстремальная ≥ 185. По классу по-прежнему задаются объём
   видеопамяти (REQ-006…009, растровая часть из них убрана), бюджетные доли, советы и баллы.
6. **Неизвестный монитор:** Full HD и 144 Гц, уверенность фактов `need.*` 0.5. Требования
   получаются желательными (0.45), как и прежде при «не знаю».
7. **Выведены из базы:** PRF-031…038 (класс по монитору), REQ-010 (видеокарта для киберспорта
   на высокой частоте), REQ-016 и REQ-017 (процессор по частоте). GOL-008 «Киберспорт на 240 Гц»
   теперь проверяет CS2 на средних настройках ≥ 240 FPS. Процессор при этом учитывается в
   прогнозе, отдельного порога 100 нет.
8. **Ослабления при невыполнимом запросе** предлагают монитор попроще из того же списка: ту же
   картинку с меньшей частотой и следующее разрешение вниз. Вариант показывается, только если
   сборка от него дешевле. Например, для современных игр «4K 60 Гц вместо 4K 144 Гц» не
   предлагается: цель и так 60 FPS.

## Последствия

- Для одиночных игр частота монитора больше не повышает требования. В Full HD Cyberpunk на
  60 FPS требует индекс 86 при 60, 144 и 240 Гц. Частота влияет только на оценку сборки
  (потолок × 1.25).
- Для соревновательных игр частота решает. CS2 в Full HD требует индекс видеокарты 18 при 60 Гц,
  43 при 144 Гц и 71 при 240 Гц.
- Разрешение влияет сильнее, чем раньше: Cyberpunk 2K — 122, 4K — 214, против прежнего
  фиксированного 185.
- Требования к процессору по данным справочника почти всегда ниже базового 85: потолки FPS игр
  на эталонном процессоре высокие. Требование «процессор от 100 для 240 Гц» было эвристикой и
  данными не подтверждалось.
- Объяснения конкретнее: «Чтобы Cyberpunk 2077 шла с комфортными 60 кадрами/с на вашем
  мониторе, нужна видеокарта с индексом от 122».
- Ответы прежних консультаций с вопросами `resolution` и `refresh_hz` по-прежнему читаются
  своими снимками БЗ. «Изменить ответы» попросит выбрать монитор заново.
- Всего правил стало 530 (−11 выведенных, +8 новых).
