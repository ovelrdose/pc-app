# ADR 0002. Машина прямого вывода: индекс фактов, вклады в факты, без TMS

- Статус: принято
- Дата: 2026-10-29
- Затрагивает: `docs/architecture.md` §5.2–5.5, код `backend/app/expert/{facts,certainty,dsl,inference,trace}`

## Контекст

Архитектура §5.5 описывает цикл «распознавание — действие» и требует зафиксировать в ADR отказ
от Rete. При реализации понадобилось уточнить ещё несколько вещей, которые §5.4 описывает
только в общих чертах: что делать, когда правило срабатывает повторно с новой уверенностью;
как разрешать конфликт значений у нечисловых фактов; что происходит с выводами после `retract`.

## Решения

1. **Индекс «факт → правила» вместо Rete.** При компиляции для каждого inference-правила
   собираются пути фактов из его условия (включая формулы). После каждого шага заново
   проверяются только правила, читающие изменившиеся факты. На ~150 inference-правилах это
   проще Rete и достаточно быстро.

2. **Одна активация на правило.** У inference-правил нет переменных, поэтому в наборе конфликтов
   не больше одной активации на правило. Порядок: `priority` ↓, специфичность (число листьев
   условия) ↓, свежесть (номер шага самого нового использованного факта) ↓, затем код правила
   (детерминизм).

3. **Рефракция по фактам и их уверенности.** Ключ рефракции — код правила и набор
   использованных фактов `(путь, значение, cf)`. Если у посылки изменилась уверенность, правило
   может сработать снова.

4. **Вклад источника заменяется, а не копится.** Факт хранит вклады по источникам (пользователь,
   каталог, конкретное правило). Повторное срабатывание правила заменяет его прежний вклад.
   Иначе каждое повторное срабатывание комбинировало бы CF по MYCIN заново и раздувало
   уверенность (0.5 → 0.75 → 0.875…). Вклады разных источников с одинаковым значением
   комбинируются по MYCIN.

5. **Конфликт значений — для любых фактов.** §5.4 описывал правило для числовых фактов; оно
   применяется ко всем: побеждает значение с большим комбинированным CF, затем с большей
   специфичностью, затем детерминированно по источникам. Ответы пользователя и данные каталога
   имеют максимальную специфичность, поэтому правило не может «перекричать» ответ при равном CF.
   Проигравшие значения хранятся у факта и попадают в трассу (исход `outvoted`). Нормировка долей
   бюджета к сумме 1 — забота конфигуратора (этап 3), а не ядра.

6. **Без системы поддержки истинности (TMS).** `retract` снимает факт целиком. Выводы, сделанные
   раньше на основании снятого факта, остаются. Inference-правила почти монотонны, а `retract`
   нужен редко; полноценный TMS усложнил бы ядро без пользы для задачи.

7. **Ошибка в правиле не останавливает вывод.** Деление на ноль, несовместимые типы и т.п.
   записываются в трассу (`rule_failed`), правило пропускается. Остановка — только при
   превышении лимита шагов (10 000), с указанием последних правил.

## Последствия

- Вывод детерминирован: одинаковые входы дают одинаковую трассу.
- Уверенность в выводах не растёт от повторных срабатываний.
- Циклы правил почти невозможны (рефракция учитывает CF), но лимит шагов остаётся страховкой.
- Нечисловые конфликты разрешаются так же, как числовые, — одно правило для всех фактов.
