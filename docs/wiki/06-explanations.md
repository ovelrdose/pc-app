# 6. Объяснения

Способность объяснить своё решение — обязательное свойство экспертной системы. Клиент должен понимать, **почему** ему предложено именно это, иначе он не поверит рекомендации.

## 6.1 Трасса — основа всех объяснений

Каждый шаг ядра записывается в **трассу** (журнал рассуждений):

| Поле записи | Пример |
|---|---|
| Этап | Профилирование |
| Правило | `REQ-024` «Монтаж требует 32 ГБ ОЗУ» |
| На каких фактах сработало | `profile.video_editing_weight = 0.3` |
| Что сделало | `req.ram_min_gb := 32` |
| Уверенность | 0.8 × 0.3 = 0.24 |
| Текст для человека | «Для монтажа видео нужно не меньше 32 ГБ памяти: таймлайн и кэш занимают много места» |

Для каждого изменённого факта записывается, чем закончилось действие: факт **новый**, **усилен** (второе правило подтвердило), **заменён** (победило другое значение), **проиграл** (у правила было своё значение, но победило чужое) или **снят**. Если правило не удалось вычислить, в трассу попадает ошибка с кодом правила.

Трасса сохраняется вместе со сборкой, поэтому объяснение доступно и через месяц.

> Запись трассы для этапа профилирования сверена с кодом: 2026-10-29. Записи остальных этапов и ответы на вопросы из §6.2 появятся на этапах 3–6.

Помимо сработавших правил, в трассу попадают:
- **отсеянные товары** с правилом-причиной (этап фильтрации);
- **отброшенные сочетания** с правилом совместимости (этап поиска);
- **разбивка полезности** каждой выбранной детали: вклад в каждый сценарий, баллы, штрафы.

## 6.2 Четыре вопроса, на которые отвечает система

### «Почему эта деталь?»

Для каждой детали сборки система собирает цепочку правил, которые к ней привели:

> **Почему RTX 5060 Ti 16 ГБ?**
> - Вы в основном играете на мониторе 1440p, поэтому видеокарта получила 40% бюджета (~48 000 ₽).
> - Для 1440p нужна видеокарта не ниже среднего+ класса.
> - Среди подходящих по цене она даёт больше всего FPS на рубль в выбранных вами играх.
> - 16 ГБ видеопамяти хватит для ультра-настроек в 1440p ещё на несколько лет.

### «Как система это вывела?»

Цепочка от ответа клиента до вывода — для любого факта:

```
«ОЗУ ≥ 32 ГБ» ← REQ-024 ← «вторичный сценарий: монтаж» ← PRF-021 ← ваш ответ «иногда монтаж»
```

### «Почему не вот эта деталь?»

> Сверено с кодом (ядро): 2026-10-29. Ответы: отсеяна правилом, нет в наличии или карточка не заполнена, категория не нужна, деталь у вас уже есть, несовместима (все нарушенные правила; при «Заменить» остальное подберётся заново), не влезает в бюджет, хуже на X% (с разницей FPS) или не хуже — можно подставить. В интерфейсе: поле «Почему не этот товар?» на вкладке «Состав» страницы сборки и список замен в меню детали.

Клиент выбирает любой товар из каталога: «А почему не RTX 5070?». Система проверяет его и отвечает конкретно:

| Причина | Пример ответа |
|---|---|
| Отсеян фильтром | «Корпус чёрный, а вы выбрали белую сборку (правило FLT-004)» |
| Нет в наличии | «Сейчас нет в наличии» |
| Несовместим | «Длина 338 мм, а корпус вмещает видеокарты до 330 мм (CMP-008)» |
| Не влезает в бюджет | «С ней сборка выходит за бюджет на 14 000 ₽» |
| Проиграл по пользе | «Подходит, но на 12% медленнее в ваших играх при той же цене» |
| Неполные данные | «Карточка товара заполняется, пока недоступен для подбора» |

Если товар вообще подходит, система предлагает кнопку «Поставить в сборку», и это работает как правка «Заменить». Рядом с ответом показывается разница: цена, полезность и FPS в процентах.

### «Что если?» / «Потянет ли?»

> Сверено с кодом: 2026-10-29. Пример дерева — на [странице 8](08-walkthrough.md#шаг-8-клиент-спрашивает-и-правит). В интерфейсе — вкладка «Потянет ли?»: список целей (игры × пресеты, программы × уровни, общие цели вроде «готова к 4K»), кнопка «Проверить»; если не хватает данных, появляются вопросы с вариантами и кнопка «Ответить и проверить».

Проверка гипотез обратным выводом ([страница 3](03-inference-engine.md#35-обратный-вывод-от-гипотезы-к-фактам)). Клиент выбирает игру или программу и настройки. Система строит дерево доказательства и показывает его: какие условия выполнены (✅), какие нет (❌) и почему, чего не хватает (❓, с вопросом клиенту).

### «Почему ничего не подобралось?»

Если требования невыполнимы в бюджет, система не выдаёт молча слабую сборку, а объясняет ([страница 4](04-configurator.md#410-если-требования-невыполнимы)):
- **что мешает**: «без требования к видеокарте для Cyberpunk 2077 в 4K (REQ-053) сборка стоила бы от 149 410 ₽»;
- **как ослабить**: «Монитор „2K, 144–180 Гц“ вместо „4K, 120–165 Гц“ → от 112 990 ₽»;
- **что можно собрать сейчас**: лучшую сборку в бюджете со списком невыполненных требований и правилами, которые их задают.

## 6.3 Два уровня подробности

| | Обычный режим (по умолчанию) | Экспертный режим (переключатель) |
|---|---|---|
| Для кого | Клиент | Любопытный клиент, консультант, защита курсовой |
| Что видно | Тексты объяснений простым языком | Коды правил, уверенности, полное дерево вывода, проигравшие правила при конфликтах, разбивка полезности по сценариям |
| Пример | «Для монтажа нужно не меньше 32 ГБ памяти» | `REQ-024` · cf 0.8 × 0.3 = **0.24** · сработало на `profile.video_editing_weight = 0.3` · вывод `req.ram_min_gb = 32` · статус: желательное (cf < 0.5) |

На странице сборки переключатель «Экспертный режим» действует на все вкладки:
- «Почему так»: вместо нумерованного списка объяснений — таблица шагов вывода (код и название правила, CF правила × CF посылки, выведенные факты с уверенностью), числовая полезность и вклад каждой задачи, коды правил у пожеланий;
- замечания и ответы «почему не» — с кодами правил;
- дерево «Потянет ли?» — с видом узла, кодом правила и CF.

Проигравшие при конфликте правила в интерфейсе пока не показываются: они есть только в трассе.

## 6.4 Откуда берутся тексты

У каждого правила обязательно есть поле `explain` — шаблон текста с подстановкой значений:

```
explain: "Блок питания {build.psu.wattage} Вт слабоват: для этой сборки нужно не меньше
          {ceil((build.cpu.tdp_w + build.gpu.tbp_w + 75) * 1.3)} Вт."
```

Без объяснения правило нельзя опубликовать. Поэтому у каждого решения системы есть человеческое обоснование.

## 6.5 Объяснения в PDF

PDF-спецификация сборки содержит:
- состав, цены и итог;
- краткое обоснование по каждой детали («почему»);
- прогноз производительности;
- предупреждения и советы.

Дата расчёта и версия базы знаний указываются, чтобы было понятно, на каких данных сделан вывод.
