# 9. Глоссарий

| Термин | Простыми словами | Где подробнее |
|---|---|---|
| **Экспертная система (ЭС)** | Программа, которая рассуждает по записанным знаниям эксперта и объясняет свои решения | [1](01-overview.md) |
| **База знаний (БЗ)** | Фреймы + правила + справочники — всё, что система «знает» | [2](02-knowledge.md) |
| **Фрейм** | Шаблон описания объекта (например, «Процессор») | [2.1](02-knowledge.md#21-фреймы) |
| **Слот** | Характеристика во фрейме (сокет, TDP, цена) | [2.1](02-knowledge.md#21-фреймы) |
| **Наследование** | Потомок фрейма получает все слоты родителя | [2.1](02-knowledge.md#21-фреймы) |
| **Вычисляемый слот** | Характеристика, которая считается сама (общая цена сборки) | [2.1](02-knowledge.md#21-фреймы) |
| **Продукционное правило** | «ЕСЛИ условие ТО действие» с объяснением | [2.2](02-knowledge.md#22-продукционные-правила) |
| **Вид правила (kind)** | Роль правила: вывод, фильтр, совместимость, оценка, проверка, цель | [2.2](02-knowledge.md#22-продукционные-правила) |
| **Группа правила (префикс)** | О чём правило: PRF — профиль клиента, REQ — требования, BUD — бюджет, FLT — фильтры, CMP — совместимость, BAL — баланс, SCR — предпочтения, VAL — проверка сборки, GOL — цели, GEN-* — сгенерированные | [2.2](02-knowledge.md#группы-правил) |
| **Приоритет (salience)** | Важность правила при выборе, что применить первым | [3.2](03-inference-engine.md#32-какое-правило-применить-первым) |
| **Специфичность** | Насколько правило конкретно (число условий). Конкретное важнее общего | [3.2](03-inference-engine.md#32-какое-правило-применить-первым) |
| **Факт** | Одно утверждение о текущей ситуации со значением и уверенностью | [2.3](02-knowledge.md#23-факты-и-рабочая-память) |
| **Рабочая память** | «Блокнот» с фактами одной консультации | [2.3](02-knowledge.md#23-факты-и-рабочая-память) |
| **Машина вывода** | Механизм, который применяет правила к фактам | [3](03-inference-engine.md) |
| **Прямой вывод** | От фактов к выводам: «что из этого следует?» | [3.1](03-inference-engine.md#31-прямой-вывод-от-фактов-к-выводам) |
| **Обратный вывод** | От гипотезы к фактам: «правда ли, что…?» | [3.5](03-inference-engine.md#35-обратный-вывод-от-гипотезы-к-фактам) |
| **Набор конфликтов** | Все правила, применимые в данный момент | [3.1](03-inference-engine.md#31-прямой-вывод-от-фактов-к-выводам) |
| **Разрешение конфликтов** | Выбор одного правила из применимых | [3.2](03-inference-engine.md#32-какое-правило-применить-первым) |
| **Рефракция** | Правило не срабатывает повторно на тех же фактах с той же уверенностью | [3.2](03-inference-engine.md#32-какое-правило-применить-первым) |
| **Вклад** | «Показание» одного источника (клиента или правила) о факте. Повторное срабатывание правила заменяет его вклад, а не добавляет новый | [3.4](03-inference-engine.md#34-уверенность-cf) |
| **Индекс «факт → правила»** | Справочник ядра: какие правила проверять при изменении факта | [3.1](03-inference-engine.md#31-прямой-вывод-от-фактов-к-выводам) |
| **Коэффициент уверенности (CF)** | Насколько система уверена в факте или правиле, от 0 до 1 | [3.4](03-inference-engine.md#34-уверенность-cf) |
| **Обязательное / желательное требование** | Требование с уверенностью ≥ 0.5 / < 0.5 | [3.4](03-inference-engine.md#34-уверенность-cf) |
| **Цель, подцель** | Гипотеза для обратного вывода и её составные части | [3.5](03-inference-engine.md#35-обратный-вывод-от-гипотезы-к-фактам) |
| **Askable-факт** | Факт, который система может спросить у клиента во время обратного вывода | [3.5](03-inference-engine.md#35-обратный-вывод-от-гипотезы-к-фактам) |
| **Компиляция правил** | Подготовка правил к быстрому применению при загрузке снимка | [3.6](03-inference-engine.md#36-как-ядро-подхватывает-новые-правила) |
| **Детерминизм** | Одинаковый вход → одинаковый результат | [3.7](03-inference-engine.md#37-детерминизм) |
| **Конфигуратор** | Часть ядра, которая собирает конкретные сборки | [4](04-configurator.md) |
| **Кандидат** | Товар, который проверяется на допустимость | [4.3](04-configurator.md#43-этап-2-фильтрация) |
| **Коридор цен** | Предпочтительный диапазон цен, в котором ищутся детали категории (60–150% от доли); к нему добавляются три самых дешёвых товара | [4.4](04-configurator.md#44-этап-3-поиск) |
| **Beam search (поиск лучом)** | Перебор, при котором на каждом шаге остаются N лучших вариантов | [4.4](04-configurator.md#44-этап-3-поиск) |
| **Доводка остатка (upgrade-pass)** | Трата остатка бюджета на самый выгодный апгрейд | [4.4](04-configurator.md#44-этап-3-поиск) |
| **Полезность** | Число: насколько сборка хороша для этого клиента | [4.5](04-configurator.md#45-этап-4-оценка-что-такое-полезность) |
| **Эконом / оптимум / максимум** | Три варианта сборки | [4.7](04-configurator.md#47-три-варианта) |
| **Фиксация (lock)** | Деталь не меняется при пересчётах | [4.8](04-configurator.md#48-правки-сборки) |
| **Апгрейд** | Подбор вокруг деталей, которые у клиента уже есть (цена 0 ₽) | [4.9](04-configurator.md#49-апгрейд) |
| **Индекс производительности** | Скорость детали относительно эталона (= 100) | [5.1](05-performance.md#51-индексы-производительности) |
| **Потолок CPU / GPU** | Максимальный FPS, который может обеспечить деталь | [5.3](05-performance.md#53-как-считается-fps) |
| **Узкое место (bottleneck)** | Деталь, которая тормозит остальные | [5.4](05-performance.md#54-узкое-место-bottleneck) |
| **Соотношение CPU/GPU** | Потолок CPU ÷ потолок GPU: показатель баланса | [5.4](05-performance.md#54-узкое-место-bottleneck) |
| **Факты прогноза** | Средний FPS, соотношение CPU/GPU и раскрытие видеокарты в играх клиента; их читают правила баланса | [5.3](05-performance.md#53-как-считается-fps) |
| **Индекс нагрузки программы** | Индекс той детали, на которой считает программа: одно ядро, все ядра или видеокарта | [5.5](05-performance.md#55-программы) |
| **Дерево доказательства** | Результат обратного вывода: цель, подцели и их исходы (доказано / опровергнуто / неизвестно) | [3.5](03-inference-engine.md#35-обратный-вывод-от-гипотезы-к-фактам) |
| **Трасса** | Журнал всех шагов рассуждения — основа объяснений | [6.1](06-explanations.md#61-трасса--основа-всех-объяснений) |
| **Экспертный режим** | Подробные объяснения: коды правил, уверенности, дерево вывода | [6.3](06-explanations.md#63-два-уровня-подробности) |
| **Ревизия каталога** | Номер, который растёт при любом изменении каталога | [7.2](07-updates.md#72-каталог-новые-детали-цены-наличие) |
| **Справочник** | Таблица, из которой генерируются однотипные правила | [7.3](07-updates.md#73-справочники-и-сгенерированные-правила) |
| **Генератор правил** | Программа, создающая правила из справочников | [7.3](07-updates.md#73-справочники-и-сгенерированные-правила) |
| **Статус товара** | Активен / неполный / требует знаний / неактивен | [7.4](07-updates.md#74-статусы-товаров) |
| **Черновик** | Правки правил, которые ещё не влияют на клиентов | [7.5](07-updates.md#75-правила-черновик--проверка--публикация) |
| **Снимок БЗ** | Замороженная проверенная версия базы знаний | [7.5](07-updates.md#75-правила-черновик--проверка--публикация) |
| **Публикация / откат** | Переключение системы на новый снимок / возврат к старому | [7.5](07-updates.md#75-правила-черновик--проверка--публикация) |

| **Словарь фактов** | Список всех фактов, которые могут быть в блокноте, с их типами; по нему проверка базы знаний ловит опечатки в правилах | [2.3](02-knowledge.md#23-факты-и-рабочая-память) |

| **Обязательное / желательное требование** | Требование с уверенностью ≥ 0.5 отсеивает товары; меньше — только даёт баллы | [3.4](03-inference-engine.md#34-уверенность-cf) |
| **Пробный прогон (dry-run)** | Проверка импорта без изменения данных | [7.2](07-updates.md#72-каталог-новые-детали-цены-наличие) |
